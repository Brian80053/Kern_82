## 1. 최소 프로그램과 실행

```kern
PROZEDUR main()
BEGIN
    AUSGABE("Hallo, Welt!");
END
```

- 진입점은 매개변수와 반환값이 없는 **`PROZEDUR main()`**이다. 정의는 하나만 있어야 한다.
- 실행 루트에는 `MODUL`을 쓰지 않는다. 모듈 안의 `main`, generic `main`은 금지한다.
- 함수·프로시저의 프로토타입만 있고 정의가 없으면, 사용하지 않아도 오류다.
- `main`에는 `RÜCKGABE;`를 쓸 수 있지만 정수 종료 코드를 반환할 수 없다.

```powershell
kern check main.k82                 # 검사만; GCC 불필요
kern run main.k82                   # C99 생성·GCC 컴파일·실행
kern main.k82                      # run과 동일
kern build main.k82 -o app.exe      # 실행하지 않고 결과 보존
```

`build`의 기본 Windows 결과는 소스 옆 `main.exe`다. 기존 `kern82 main.k82 -o main.c`는 C99 출력 명령이다. `kern` 실행에는 설치의 `bin` 폴더를 PATH에 추가하고, run/build에는 별도로 GCC를 준비한다.

## 2. 기본 자료형

| 타입 | 저장·범위 | 초기값 / 핵심 의미 |
|---|---|---|
| `GANZ` | signed 16-bit, −32,768…32,767 | `0` |
| `LANG` | signed 32-bit, −2,147,483,648…2,147,483,647 | `0` |
| `GLEIT` | 4바이트 단정밀도 실수; 현 Windows/GCC에서 약 ±3.4×10³⁸, 유효숫자 약 6–7자리 | `0.0`; NaN·무한대 결과는 오류 |
| `BOOL` | `FALSCH`, `WAHR`; 현 Windows/GCC에서 1바이트인 C99 `bool`, 1비트 압축 아님 | `FALSCH`; 정수와 별도 타입 |
| `CHAR` | unsigned 8-bit, 0…255 | NUL(`0`); Kern 문자 코드 한 개 |
| `KETTE` | 고정 용량의 CHAR 저장소 + 현재 길이 | 빈 문자열; NUL 종료 방식 아님 |

배열·STRUCT도 기본값으로 재귀 초기화한다. 포인터와 함수 포인터는 `NULL`, ENUM은 ordinal `0`이다. KETTE의 전체 저장 크기는 용량뿐 아니라 길이 정보·정렬을 포함한다. 포인터·STRUCT·BOOL의 이식 가능한 바이너리 레이아웃이나 `sizeof` 문법을 제공한다고 가정하지 않는다.

## 3. 리터럴과 변환

| 종류 | 예 | 제한 |
|---|---|---|
| 정수 | `0`, `123`, `-32768` | 10진수. 16진·2진 표기 없음 |
| 실수 | `1.5`, `1e3`, `2.5E-2` | 소수점 사용 시 양쪽에 숫자 필요. `.5`, `1.` 불가 |
| 논리 | `WAHR`, `FALSCH` | 정수 `0`/`1`을 대신 쓸 수 없음 |
| 문자 | `'A'`, `'Ü'`, `'\0'` | 정확히 Kern 문자 1개 |
| 문자열 | `"A"`, `"ÄÖÜ"` | CHAR와 다른 리터럴 타입. 일반 변수의 선언 타입으로 사용 불가 |
| 널 포인터 | `NULL` | 대상 포인터 타입 문맥 필요. `FREIGEBEN(NULL)`은 허용 |

이스케이프는 `\n`, `\r`, `\t`, `\0`, `\\`, `\'`, `\"`만 지원한다. 리터럴 안의 실제 줄바꿈은 금지한다. 문자열 리터럴과 CHAR 사이의 암시적 변환은 없다: `CHAR x = "Ü";`는 오류다.

```kern
LANG wide = 40000;
GANZ n = GANZ(3.9);
CHAR letter = CHAR(65);
GANZ code = GANZ('Ü');
GLEIT f = GLEIT(wide);
```

- 명시적 숫자 변환은 `GANZ(expr)`, `LANG(expr)`, `GLEIT(expr)`, `CHAR(expr)` 및 해당 명목 타입 이름으로 한다.
- 실수 → 정수는 0 방향으로 소수부를 버리고 범위를 검사한다. 정수 → 실수는 반올림될 수 있다.
- `BOOL`은 숫자 변환 대상이 아니다. 포인터 변환은 지원하지 않는다.
- 정수 리터럴은 문맥에 따라 GANZ/LANG/GLEIT 및 숫자 명목 타입을 취한다. 문맥이 없으면 GANZ 범위는 GANZ, 그 밖은 LANG이다. GLEIT 문맥의 정수 리터럴은 절댓값 16,777,216 이하로 제한된다.
- 리터럴의 문맥 적응이 일반 변수 간 암시적 변환을 의미하지는 않는다. 예: LANG 변수에 GANZ 변수를 넣으려면 `LANG(x)`를 쓴다.

## 4. 선언·KONST·REGISTER·식별자

```kern
GANZ x = 10;
KONST GANZ MAX = 100;
REGISTER GANZ i;
KONST REGISTER LANG mask = 255;
```

- 선언 하나에 이름 하나. `GANZ a, b;`와 복합 대입 `+=` 등은 지원하지 않는다.
- 일반 변수의 생략 초기화는 정의된 기본값을 사용한다. 지역 초기화는 식을 사용할 수 있다.
- 전역 스칼라 초기화는 리터럴·ENUM 값·NULL 및 이들로 구성한 단항/이항/변환 식으로 제한된다. 다른 변수·루틴 호출·`ADDRESSE`·동적 할당은 사용할 수 없다. 전역의 포인터를 연결하려면 `main` 등에서 대입한다.
- `KONST` 스칼라는 초기화가 필요하며 재대입·입력·증감을 금지한다. KONST 배열은 명시적 초기화 문법 없이 기본 초기화되며, KONST KETTE는 문자열 리터럴 초기화가 필요하다. KONST STRUCT와 KONST REFERENZ는 지원하지 않는다.
- `REGISTER`는 허용되는 선언 표시일 뿐, 레지스터 배치·최적화·주소 취득 제한을 보장하지 않는다. 둘을 함께 쓰면 `KONST REGISTER 타입 이름` 순서다.
- 키워드는 대문자이며 이름은 대소문자를 구분한다. 식별자는 `_` 또는 지원 문자셋의 문자로 시작하고, 이후에는 숫자도 허용한다. `größe` 같은 이름은 유효하다.
- 주석은 `/* ... */`이며 중첩하지 않는다. `//` 주석은 없다. 소스와 주석에도 현재 문자셋 검사가 적용된다.
- 선언·식 문장·return·break류·IMPORT·프로토타입에는 `;`를 쓴다. IF/반복 블록 끝에는 필요 없다. TYP ENUM/STRUCT의 마지막 `END` 뒤 `;`는 선택 사항이다.

## 5. 연산자·평가 순서

우선순위 **높음 → 낮음**. 이항 연산자는 왼쪽 결합, 대입은 오른쪽 결합이다.

| 우선순위 | 연산자 | 조건 |
|---:|---|---|
| 1 | 호출, `.`, `[]`, 후위 `++ --` | 호출/멤버/인덱스. 후위 증감은 변경 전 값 반환 |
| 2 | 전위 `++ --`, `+ -`, `! NOT`, `~` | 증감: GANZ/LANG·해당 명목 타입·데이터 포인터; `+ -`: 숫자; `! NOT`: BOOL; `~`: 정수 |
| 3 | `* / %` | `%`는 정수만 |
| 4 | `+ -` | 숫자; 별도 포인터 규칙은 §17 |
| 5 | `<< >>` | 같은 정수 타입. 시프트 수는 0 이상 폭(16/32) 미만 |
| 6 | `< <= > >=` | 같은 숫자 타입 또는 CHAR 계열 |
| 7 | `== !=` | 숫자·CHAR·BOOL·동일 ENUM |
| 8 | `&` | 정수 비트 AND |
| 9 | `^` | 정수 비트 XOR |
| 10 | `\|` | 정수 비트 OR |
| 11 | `&& AND` | BOOL 논리 AND, 단락 평가 |
| 12 | `XOR` | BOOL 논리 XOR, 양쪽 평가 |
| 13 | `\|\| OR` | BOOL 논리 OR, 단락 평가 |
| 14 | `=` | 수정 가능한 저장소에 같은 타입 대입, 대입한 값 반환 |

- BOOL과 정수는 섞이지 않는다. 조건식에는 정확히 BOOL이 필요하며 truthy/falsy 규칙은 없다.
- 같은 기반 숫자형이어도 서로 다른 명목 타입 피연산자는 명시적 변환이 필요하다.
- 정수 나눗셈은 0 방향 절삭, 나머지는 피제수의 부호를 따른다. 0으로 나누면 런타임 오류다.
- 정수 산술·증감·왼쪽 시프트는 결과 범위를 검사한다. 비트 연산은 해당 16/32비트 폭으로 정의되며, 오른쪽 시프트는 부호를 보존한다.
- 피연산자·호출 인수는 왼쪽부터 평가한다. 읽은 값은 평가 시점 값으로 유지된다. `f(i++, i++)`는 순서가 정의된다.
- 삼항 연산자, IF expression, `===`, 오버로드 연산자, C의 단항 `*`/`&`는 없다.

## 6. 블록과 스코프

```kern
GANZ x = 1;
BEGIN
    GANZ x = 2;
    AUSGABE(x);
END
AUSGABE(x);
```

출력은 `2`, `1`. BEGIN/END는 lexical scope를 만든다. 같은 스코프의 중복 선언은 금지하고 내부 블록의 shadowing은 허용한다. 지역 변수는 선언 이후에만 보인다. 매개변수와 루틴 최상위 지역 변수는 같은 스코프다.

타입도 사용 전에 선언해야 한다. 타입 이름과 값 이름의 같은 스코프 충돌은 금지하며, 내부 값 선언으로 바깥 타입 이름을 가릴 수 있다. 전역 값과 일반 루틴은 별도 수집되므로 지역 변수와 같은 선언 순서 제한을 그대로 적용하지 않는다.

## 7. IF / ELSE IF / ELSE

```kern
GANZ x = -1;
IF x > 0 THEN
BEGIN
    AUSGABE("positive");
END
ELSE IF x < 0 THEN
BEGIN
    AUSGABE("negative");
END
ELSE
BEGIN
    AUSGABE("zero");
END
```

- `ELSE IF`는 ELSE와 IF 두 토큰이다. 반복해서 연결할 수 있고 최종 ELSE는 선택 사항이다.
- 모든 조건은 BOOL. 위에서 아래로 평가하고 첫 참 분기만 실행한다. 이후 조건은 평가하지 않는다.
- IF와 ELSE IF는 `THEN BEGIN ... END`, ELSE는 `BEGIN ... END`가 필수다. 단일 문장 축약은 없다.
- 분기마다 독립 스코프. 중첩 IF도 동일한 규칙이다. 조건식 자체의 괄호는 선택 사항이다.

## 8. SWITCH / CASE / DEFAULT / FALLTHROUGH

```kern
GANZ code = 1;
SWITCH code
BEGIN
    CASE 1:
        AUSGABE("one");
        FALLTHROUGH;
    CASE 2:
        AUSGABE("two");
    DEFAULT:
        AUSGABE("other");
END
```

출력은 `one`, `two`. SWITCH 식은 한 번 평가한다.

- 대상은 GANZ/LANG/CHAR 계열 또는 ENUM. BOOL/GLEIT은 불가하다.
- CASE는 선택식 타입에 맞는 컴파일 타임 상수다. 상수 연산 및 해당 타입의 KONST를 사용할 수 있다. ENUM은 같은 ENUM의 값을 쓴다.
- 같은 값의 CASE는 중복 오류다. 서로 다른 이름의 ENUM alias라도 ordinal이 같으면 중복이다.
- DEFAULT는 최대 하나이며 마지막 위치일 필요는 없다. 어느 CASE도 일치하지 않을 때 선택한다.
- CASE 본문은 `CASE 값:`부터 다음 CASE/DEFAULT/END까지다. 추가 BEGIN/END는 선택 사항이며, 각 arm 자체도 별도 스코프다.
- 암시적 fallthrough는 없다. `FALLTHROUGH;`만 다음 **소스상 arm**으로 이동한다. 그 arm의 CASE 조건을 다시 검사하지 않는다.
- FALLTHROUGH는 다음 arm이 있어야 하며 해당 분기에서 마지막 실행 문장이어야 한다. CASE 안 IF의 말단 분기에는 사용할 수 있으나 반복문 내부 사용 등은 검사에 걸린다.
- `ABBRUCH`는 SWITCH 종료 명령이 아니다. SWITCH가 반복문 안에 있으면 가장 가까운 반복문을 끝낸다. 반복문 밖에서는 오류다.

## 9. WHILE / FOR

```kern
GANZ n = 3;
WHILE (n > 0)
BEGIN
    n--;
END
FOR (GANZ i = 0; i < 3; i++)
BEGIN
    AUSGABE(i);
END
FOR (;;)
BEGIN
    ABBRUCH;
END
```

- WHILE은 괄호 필수, 본문은 BEGIN/END 필수다.
- FOR는 `FOR (초기식; 조건식; 증감식) BEGIN ... END`. 각 절은 독립적으로 생략 가능하며, 조건 생략은 참이다. 무한 루프는 `FOR (;;)`이다.

- 초기절은 선언 하나 또는 식 하나, 증감절은 식 하나다. 쉼표로 여러 초기식·증감식을 나열하지 않는다.
- 조건은 BOOL. FOR 초기절의 변수는 조건·증감·본문에서만 보인다. 중첩 FOR는 안쪽에서 같은 이름을 shadowing할 수 있다.

## 10. ABBRUCH / WEITER

- `ABBRUCH;`: 가장 가까운 반복문 종료.
- `WEITER;`: 가장 가까운 반복문의 다음 반복. FOR에서는 **증감절 실행 후** 조건 검사, WHILE에서는 조건 검사로 이동한다.
- 반복문 밖에서는 둘 다 오류다. 나가는 블록의 지역 저장소 수명은 끝난다.

## 11. FUNKTION / PROZEDUR

```kern
FUNKTION GANZ add(GANZ a, GANZ b);

FUNKTION GANZ add(GANZ a, GANZ b)
BEGIN
    RÜCKGABE a + b;
END

PROZEDUR print(GANZ x)
BEGIN
    AUSGABE(x);
    RÜCKGABE;
END
```

- FUNKTION은 반환형과 `RÜCKGABE 값;`, PROZEDUR은 반환값 없이 종료 또는 `RÜCKGABE;`를 쓴다.
- 일반 매개변수는 값 전달. 변경을 전달하려면 REFERENZ 또는 ZEIGER를 사용한다. 배열/KETTE/non-copyable STRUCT 값 전달·반환은 금지한다.
- 매개변수 목록은 각 항목마다 타입과 이름을 쓴다. 기본 인수·가변 인수·사용자 루틴 오버로딩·루틴 내부의 루틴 선언은 없다.
- 본문 대신 `;`이면 프로토타입. 정의와 이름·반환형·매개변수 타입/개수가 일치해야 한다. 매개변수 이름까지 같을 필요는 없다.
- 직접 재귀·상호 재귀 지원. 일반 최상위 루틴의 호출은 정의 순서에 묶이지 않지만, 시그니처에 사용한 타입은 먼저 선언되어야 한다.
- 함수는 분석 가능한 모든 종료 경로에서 반환해야 한다. IF/ELSE 및 DEFAULT를 포함한 SWITCH 반환 경로를 검사한다. 반복문이 무한히 돈다는 사실은 반환 보장으로 인정하지 않는다.
- 참조 반환은 §18, 함수 포인터는 §20.

## 12. 배열

```kern
GANZ a[10];
GANZ matrix[2][3];
matrix[1][2] = 7;
ZEIGER GANZ element = ADDRESSE(matrix[1][0]);
AUSGABE(INHALT(element + 2));
```

- 정적 고정 크기·다차원 배열. 차원별 크기는 양의 정수 상수 **식**이며 최대 2,147,483,647이다. 현재 크기 식은 정수 리터럴과 정수 연산으로 구성해야 하며 변수·KONST 이름·함수 호출을 사용하지 않는다.
- VLA와 배열 초기화 목록은 없다. 전 원소가 기본 초기화된다.
- 인덱스는 정확히 GANZ 또는 LANG이다. CHAR/BOOL/ENUM/숫자 nominal TYP 인덱스는 명시적으로 변환한다.
- 각 차원에서 `0 <= index < dimension`을 런타임 검사한다.
- 배열과 부분 배열은 non-copyable. 전체 대입·비교·출력·값 전달·반환·slicing은 지원하지 않는다.
- array-to-pointer decay는 없다. 최종 원소의 주소만 취한다. 다차원 배열에서 얻은 원소 포인터의 산술 범위는 해당 마지막 차원의 배열이며 다음 행으로 넘어가지 않는다.

## 13. KETTE

```kern
KETTE name[8] = "Kern";
name[4] = ' ';
name[5] = '8';
name[6] = '2';
AUSGABE(name);
CHAR first = name[0];
```

`[8]`은 **capacity**이며 위의 current length는 7이다. 길이의 단위는 UTF-8 바이트 수가 아니라 Kern CHAR 수다.

| 연산 | 규칙 |
|---|---|
| 선언 | `KETTE s[용량];` 또는 문자열 리터럴 초기화. 생략 시 길이 0 |
| 초기화 | 리터럴의 Kern 문자 수가 capacity 이하. 다른 KETTE로 초기화 불가 |
| 읽기 `s[i]` | `0 <= i < current length` |
| 덮어쓰기 | `0 <= i < current length`인 원소에 CHAR 저장 |
| append | `i == current length`이고 `i < capacity`일 때 길이 1 증가 |
| 잘못된 쓰기 | 끝을 건너뛰거나 capacity 이상이면 오류. 자동 확장 없음 |
| 주소·참조 취득 | 이미 존재하는 문자만 가능. append 위치는 불가 |
| 전체 연산 | 대입·비교·연결·일반 값 전달/반환 금지 |

- NUL 종료 문자열이 아니다. `KETTE s[3] = "A\0B";`는 길이 3이며 출력도 세 문자를 다룬다. NUL 쓰기는 길이를 줄이지 않고 append 위치에 쓰면 길이가 증가한다.
- `LESEN(s)`는 공백으로 구분한 다음 토큰으로 내용을 교체한다. 짧아지면 길이도 줄고, capacity를 넘으면 잘라 저장하지 않고 오류다.
- `LESEN(s[i])`도 CHAR 쓰기/append 규칙을 따른다.
- 인덱스·대상은 한 번 평가하고 오른쪽 값의 부작용 전후에 쓰기 가능 범위를 검사한다.
- `CHAR a[n]`는 길이 n인 배열이고 빈/현재 길이 개념이 없다. KETTE와 서로 변환·대입하지 않는다. 일반 길이 조회·resize·concat 내장 API는 없다.

## 14. TYP: alias가 아닌 nominal type

```kern
TYP Meter = GANZ;
TYP Sekunde = GANZ;

PROZEDUR main()
BEGIN
    Meter m = 10;
    Sekunde s = Sekunde(m);
    GANZ raw = GANZ(m);
    AUSGABE(m + 2, " ", raw, " ", s);
END
```

- 같은 기반형이라도 Meter·Sekunde·GANZ는 서로 다른 타입이다. 변수 간 대입/호출과 연산에서 자동으로 섞이지 않는다.
- 리터럴은 기대 타입에 맞출 수 있다. 숫자 nominal 타입은 기반형의 연산과 범위 검사를 유지한다.
- 숫자/CHAR 기반 명목 타입은 허용된 스칼라끼리 명시 변환 가능하다. BOOL 계열의 정수 변환은 금지한다.
- 동일 기반 ENUM/STRUCT와 그 TYP 사이에는 compatible aggregate 변환이 가능하되 copyability가 필요하다. 별도로 선언한 두 STRUCT/ENUM을 같은 모양이라는 이유로 변환할 수 없다.
- TYP은 지역 블록에도 선언 가능하다. 같은 철자의 다른 스코프 선언도 별도 타입이다. 타입/값 이름 충돌·shadowing은 §6을 따른다.
- 포인터 타입을 기반으로 하는 TYP도 가능하지만 포인터 명시 cast는 별도로 금지되어 있다. REFERENZ를 TYP으로 정의할 수는 없다.

## 15. ENUM

```kern
TYP ENUM Status
BEGIN
    AUS = -1,
    BEREIT = 8,
    AKTIV,
    START = 9,
END

PROZEDUR main()
BEGIN
    Status s = AKTIV;
    AUSGABE(LANG(s), " ", s == START);
END
```

- 형식은 `TYP ENUM 이름 BEGIN ... END`. 최소 한 멤버가 필요하다. 마지막 쉼표 허용.
- ordinal은 signed 32-bit. 처음 생략값은 0, 이후 생략값은 직전 값 + 1이다. 명시값·자동값 혼합과 값 alias를 허용한다.
- 명시값은 정수 상수 식. 앞서 선언한 평가 가능한 KONST GANZ/LANG 이름을 사용할 수 있다. 멤버 이름은 같은 값 스코프에 도입되며 이름 중복은 금지한다.
- 초기화 없는 ENUM 변수의 저장값은 **0**이다. 첫 멤버 값도 아니고, 선언된 멤버 중 하나라는 보장도 없다.
- 같은 ENUM끼리 대입·전달·반환·`== !=` 및 SWITCH 사용 가능. 산술·순서 비교·증감·직접 입출력은 금지한다.
- ordinal을 꺼낼 때 `LANG(s)` 또는 `GANZ(s)`를 쓴다. GANZ 범위를 벗어나면 오류다. 정수 → ENUM, ENUM → GLEIT/CHAR/BOOL 및 숫자 nominal TYP 변환은 지원하지 않는다.
- alias는 비교상 같은 값이다. SWITCH의 동일 ordinal CASE 중복도 금지한다.

## 16. STRUCT

```kern
TYP STRUCT Point BEGIN GANZ x; GANZ y; END
TYP STRUCT Line BEGIN Point start; Point finish; END

TYP STRUCT Counter
BEGIN
    PRIVATE
        GANZ value;
    PUBLIC
        PROZEDUR add(GANZ amount)
        BEGIN
            value = value + amount;
        END
        FUNKTION GANZ read()
        BEGIN
            RÜCKGABE value;
        END
END

PROZEDUR main()
BEGIN
    Counter c;
    c.add(2);
    AUSGABE(c.read());
END
```

- 형식은 `TYP STRUCT 이름 BEGIN 필드/멤버루틴 END`. 기본 접근 수준은 **PUBLIC**이다. PUBLIC/PRIVATE는 이후 멤버에 적용하며 콜론을 붙이지 않는다.
- 필드는 `obj.field`, 멤버 루틴은 `obj.method(...)`. 다른 STRUCT 타입을 필드로 포함하는 중첩은 가능하다. STRUCT 본문 안에 중첩 타입 선언을 쓰지는 않는다.
- 필드는 기본 초기화한다. 필드별 초기화 식·KONST 필드·참조 필드는 금지한다. 배열·KETTE·포인터·함수 포인터 필드는 가능하다.
- 멤버 함수 내부에서 필드/동일 STRUCT의 멤버를 이름만으로 사용한다. 명시적 `self`/`this` 이름은 없다.
- 값 이름 탐색: 지역/매개변수 → 필드 → 전역. 호출 이름은 지역값/필드 → 동일 STRUCT 멤버 → 전역값/루틴 순서다. 동일 STRUCT의 다른 인스턴스 PRIVATE 멤버도 그 STRUCT의 메서드에서는 접근 가능하다.
- 멤버 프로토타입도 가능하며 정의와 접근 수준·시그니처가 일치해야 한다. 모든 메서드는 수정 가능한 receiver를 요구하므로 const view를 통해 읽기 전용처럼 생긴 메서드를 호출하는 것도 불가하다.
- 자기 자신은 포인터 필드로 참조할 수 있지만, 재귀적인 by-value 포함으로 무한 크기를 만들 수 없다.

### Copyability

| 타입 | 값 복사 가능 여부 |
|---|---|
| 기본 스칼라·ENUM·포인터·함수 포인터 | 가능 |
| TYP | 기반형의 copyability를 따름 |
| 배열·KETTE | 불가 |
| STRUCT | **멤버 루틴이 없고 모든 필드가 재귀적으로 copyable일 때만** 가능 |

PRIVATE 자체는 copyability에 영향이 없다. non-copyable 타입의 값 초기화·대입·매개변수·반환·복사 cast는 금지한다. 객체 선언·필드 조작·포인터/참조 전달은 가능하다. copyable STRUCT를 복사하면 포인터 필드도 포인터 값만 복사되어 같은 대상을 가리킨다.

## 17. ZEIGER: 데이터 포인터

```kern
GANZ x = 10;
ZEIGER GANZ p = ADDRESSE(x);
ZEIGER GANZ alias = p;
ZEIGER ZEIGER GANZ pp = ADDRESSE(p);
INHALT(INHALT(pp)) = 20;
AUSGABE(INHALT(alias));
```

포인터 변수·복사·다단계 포인터를 지원한다. 포인터 타입은 가리키는 타입의 nominal identity와 const 정보를 보존한다. `ZEIGER Meter`와 `ZEIGER Sekunde`는 서로 다른 타입이다.

### const 구분

```kern
GANZ x = 10;
KONST GANZ fixed = 20;
ZEIGER GANZ p = ADDRESSE(x);
ZEIGER KONST GANZ view = p;
ZEIGER KONST GANZ fixedView = ADDRESSE(fixed);
KONST ZEIGER GANZ fixedPointer = ADDRESSE(x);
INHALT(fixedPointer) = 30;
```

| 선언 | 변경 금지 대상 |
|---|---|
| `ZEIGER KONST T p` | p를 통해 보는 T 저장소. p 자체는 재대입 가능 |
| `KONST ZEIGER T p = ...` | 포인터 변수 p. 가리키는 T가 mutable이면 쓰기 가능 |
| `KONST ZEIGER KONST T p = ...` | 둘 다 |

mutable 포인터 → 같은 대상의 const view 변환은 가능하다. const 제거 및 다단계 포인터의 임의 const 변환은 없다. KONST 저장소의 주소는 기대 타입이 `ZEIGER KONST T`인 문맥에서 취한다. 기본 `ADDRESSE` 문맥은 mutable 저장소를 요구한다.

### 주소와 산술

| 형태 | 지원·범위 |
|---|---|
| `ADDRESSE(x)` / `INHALT(p)` | 주소 취득 / 역참조. INHALT 결과는 저장소로 사용 가능 |
| `ADDRESSE(a[i])` | 최종 배열 원소. 같은 마지막 차원 내 산술 허용 |
| `ADDRESSE(obj.field)` | 필드 접근 권한 적용. 해당 필드를 단일 객체 영역으로 취급 |
| `ADDRESSE(s[i])` | 현재 존재하는 KETTE 문자. 역참조는 가능하지만 **모든 포인터 산술 금지** |
| `p + n`, `n + p`, `p - n` | n은 정확히 GANZ/LANG. 바이트가 아닌 원소 단위 |
| `++p`, `p++`, `--p`, `p--` | 원소 한 칸 이동. 전위/후위 결과와 범위 검사 적용 |
| `p - q` | 동일 포인터 타입이고 같은 live 영역/할당 기반/원소 크기일 때 LANG 거리 |

- 포인터 결과는 항상 영역의 실제 원소 안이어야 한다. **one-past 포인터 생성도 오류**다. 단일 스칼라·필드 영역은 원소 수 1이다.
- `ADDRESSE(전체배열)`·`ADDRESSE(전체KETTE)`·배열 decay·`p[i]`는 지원하지 않는다. `INHALT(p + i)`를 쓴다.
- `p == q`, `p != NULL` 등 포인터 비교, 정수↔포인터, 데이터↔함수 포인터 변환은 지원하지 않는다.
- 이미 수명이 끝난 포인터를 복사한다고 되살아나지 않는다. 역참조·주소 재취득·산술 시 live 상태를 검사한다.

### 수명과 영역

| 저장소 | 수명 |
|---|---|
| 전역 | 프로그램 실행 동안 |
| 지역·값 매개변수 | 해당 블록/호출을 벗어나면 종료 |
| 동적 할당 | FREIGEBEN까지 |

포인터는 주소 외에 영역과 수명 identity를 유지한다. 같은 주소가 나중에 재사용되어도 이전 포인터는 유효해지지 않는다. STRUCT 필드·배열 원소의 수명은 소유 저장소를 따른다. KETTE 문자 포인터는 소유 KETTE의 수명을 따르며 이후 입력으로 current length가 줄어드는 것을 독립적인 새 수명으로 추적하지 않는다. 따라서 **현재 길이 검사가 필요한 접근은 `s[i]`를 사용**한다.

## 18. REFERENZ

```kern
FUNKTION REFERENZ GANZ same(REFERENZ GANZ x)
BEGIN
    RÜCKGABE x;
END

PROZEDUR main()
BEGIN
    GANZ x = 10;
    REFERENZ GANZ r = x;
    REFERENZ KONST GANZ view = r;
    r = 20;
    same(x) = 30;
    ZEIGER GANZ p = ADDRESSE(r);
    AUSGABE(view, " ", INHALT(p));
END
```

- non-null이며 지역 선언 시 반드시 초기화한다. 동일 타입의 주소 가능한 저장소에만 결합하고, 임시 계산값·리터럴에는 결합하지 않는다.
- 자동 역참조. `r = value`는 참조 대상 쓰기이며 **reseat가 아니다**. `ADDRESSE(r)`도 참조 대상의 주소다. `INHALT(r)`는 r 자체를 참조 해제하는 문법이 아니다; r의 값이 포인터 타입일 때만 포인터 역참조로 성립한다.
- `REFERENZ KONST T`는 읽기 전용 view. mutable → const view는 가능하지만 역방향은 금지한다. mutable 참조를 통해 KONST 저장소에 결합할 수 없다.
- 지역 변수·루틴 매개변수·루틴 반환형에 지원한다. 전역 참조·참조 필드·참조 배열·중첩 참조·포인터로 저장한 참조 타입은 지원하지 않는다.
- 배열/KETTE 전체를 참조할 수 없다. 원소·문자, 그리고 non-copyable STRUCT 자체는 참조 가능하다.
- 반환 참조는 원래 저장소·const·수명을 보존한다. 지역 저장소를 반환하는 코드를 정적으로 모두 금지하지는 않지만, 그 지역 수명이 끝난 뒤 접근하면 런타임 오류다. 참조는 대상을 연장해서 살려두지 않는다.

## 19. 동적 메모리

```kern
ZEIGER GANZ p = ALLOKIEREN(3);
INHALT(p + 1) = 42;
ZEIGER GANZ alias = p;
AUSGABE(INHALT(alias + 1));
FREIGEBEN(p);
p = NULL;
FREIGEBEN(NULL);
```

- `ALLOKIEREN(n)`의 n은 바이트 수가 아닌 **원소 개수**다. 기대되는 `ZEIGER T`가 원소 타입을 결정한다. 선언·대입·매개변수·반환의 포인터 타입 문맥에서 쓴다. 독립 `ALLOKIEREN(3);`는 불가하다.
- 개수는 정확히 GANZ/LANG. 0·음수·크기 초과·할당 실패는 런타임 오류다. 참조 원소는 할당할 수 없다.
- 원소는 기본값으로 초기화된다. 스칼라뿐 아니라 STRUCT·다단계 포인터 대상도 지원한다.
- FREIGEBEN은 동적 할당의 **기반 포인터(offset 0)**에만 허용한다. 내부 포인터·지역/전역 주소 해제는 오류다. 같은 기반을 가리키는 alias로 해제하는 것은 가능하다.
- `FREIGEBEN(NULL)`은 아무 일도 하지 않는다. 이중 해제·해제 후 접근은 오류다.
- 해제는 모든 alias가 공유하는 수명을 끝낸다. 포인터 변수들은 **자동 NULL로 바뀌지 않는다**. `p = NULL`도 다른 alias까지 변경하지 않는다.
- 자동 소유권·RAII·GC·범위 종료 시 자동 free는 없다. 사용자가 동적 할당을 해제해야 한다.

## 20. 함수 / 프로시저 포인터

```kern
FUNKTION GANZ add(GANZ a, GANZ b) BEGIN RÜCKGABE a + b; END
PROZEDUR print(GANZ x) BEGIN AUSGABE(x); END
TYP STRUCT Handler BEGIN ZEIGER PROZEDUR(GANZ) callback; END

PROZEDUR main()
BEGIN
    ZEIGER FUNKTION GANZ(GANZ, GANZ) f = ADDRESSE(add);
    ZEIGER PROZEDUR(GANZ) out = ADDRESSE(print);
    Handler h;
    h.callback = out;
    h.callback(f(2, 3));
END
```

- 반환형·순서 있는 매개변수 타입 전체가 signature identity다. nominal 타입과 REFERENZ/const도 일치해야 한다.
- 변수 호출 `f(...)`, 함수 포인터 필드 호출 `obj.callback(...)`을 지원한다. 매개변수·반환형에 REFERENZ를 포함할 수 있다.
- 초기값은 NULL. NULL 함수 포인터 호출은 런타임 오류다.
- 주소 대상은 일반 최상위 concrete routine이다. 멤버 루틴 주소·unspecialized generic 주소·closure는 지원하지 않는다.
- 산술·증감·비교·FREIGEBEN·INHALT 및 데이터 포인터와의 변환은 지원하지 않는다.

## 21. 명시적 제네릭

```kern
GENERISCH T GEORDNET
FUNKTION T minimum(T a, T b)
BEGIN
    IF a < b THEN BEGIN RÜCKGABE a; END
    ELSE BEGIN RÜCKGABE b; END
END

GENERISCH T
PROZEDUR tausche(REFERENZ T a, REFERENZ T b)
BEGIN
    T tmp = a;
    a = b;
    b = tmp;
END

FUNKTION GANZ minGanz = NEU minimum(GANZ);
FUNKTION LANG minLang = NEU minimum(LANG);
PROZEDUR swapGanz = NEU tausche(GANZ);

PROZEDUR main()
BEGIN
    GANZ a = 2;
    GANZ b = 1;
    swapGanz(a, b);
    AUSGABE(minGanz(a, b), " ", minLang(40000, 50000));
END
```

| 제약 | 허용되는 타입 능력 |
|---|---|
| 없음 | 특별한 연산 능력 요구 없음 |
| `VERGLEICHBAR` | 숫자·CHAR·BOOL·ENUM 계열의 `== !=` |
| `GEORDNET` | 숫자·CHAR 계열의 동등·순서 비교 |
| `NUMERISCH` | GANZ/LANG/GLEIT 및 숫자 nominal 타입 |

- 여러 타입 인수: `GENERISCH T GEORDNET, U` → `NEU routine(GANZ, LANG)`. 순서와 개수가 맞아야 한다.
- GENERISCH는 최상위 FUNKTION/PROZEDUR 하나에만 적용한다. 정의 본문이 필요하다. 제네릭·사용 타입은 NEU보다 먼저 정의한다.
- 함수 인스턴스 선언은 **`FUNKTION 반환형 이름 = NEU template(타입...);`**이다. 반환형 생략 문법이 아니다. 선언 반환형은 특수화 결과와 일치해야 한다.
- 타입 인수를 명시하여 컴파일 타임에 concrete routine을 만드는 monomorphization 방식이다. 런타임 generic dispatch, 호출 지점 타입 추론·암시적 인스턴스화·generic 직접 호출은 없다.
- 치환된 본문은 기존 타입·복사·const·수명 규칙을 다시 만족해야 한다. 제약 통과가 본문 전체의 성공을 보장하지 않는다.
- REFERENZ만 쓰는 제네릭은 non-copyable STRUCT에 사용할 수 있다. 값을 복사하는 위 tausche는 그런 타입으로 인스턴스화할 수 없다.
- 자기 재귀는 현재 concrete routine으로 연결된다. 다른 generic의 자동 특수화는 없다.
- 생성 결과는 일반 호출·주소 취득·포인터 저장·EXPORT·참조 반환에 사용할 수 있다. nominal 타입과 모듈 identity는 보존된다. 같은 인스턴스를 다른 이름으로 여러 번 만들 수 있다.
- generic STRUCT/ENUM/TYP/멤버/모듈, traits·overload·부분 특수화·기본 타입 인수·비타입 인수는 없다.

## 22. 모듈

**`Math.k82` — 모듈 파일:**

```kern
MODUL Math
EXPORT FUNKTION GANZ add(GANZ a, GANZ b)
BEGIN
    RÜCKGABE a + b;
END
```

**`main.k82` — 실행 루트:**

```kern
IMPORT Math;
PROZEDUR main()
BEGIN
    AUSGABE(add(2, 3));
END
```

- `MODUL 이름`은 파일 첫머리에 오며 `;`가 없다. `IMPORT 이름;`은 최상위에서 사용한다. import된 파일의 선언 이름은 요청 이름과 일치해야 한다.
- 실행 루트는 main을 제공한다. import 모듈에는 main이 없어야 한다. 모듈만 단독 `check`하면 실행 진입점이 없으므로, 검증할 때는 importer 루트를 사용한다.
- 탐색 순서는 **진입 소스 폴더 → IMPORT가 있는 소스 폴더 → 실행 파일의 `../stdlib`**이다. 로컬 파일이 우선하며 현재 shell 작업 폴더에 의존하지 않는다.
- EXPORT된 최상위 변수·상수·타입·ENUM 멤버·루틴·제네릭·concrete 인스턴스를 가져온다. 제네릭 공개 표기는 `GENERISCH T ... EXPORT FUNKTION ...`을 쓸 수 있다.
- 같은 모듈은 한 번 로드하고 순환 IMPORT는 오류다. 두 모듈의 같은 이름 nominal 타입은 서로 다른 identity다.
- import된 동명 심볼을 모호하게 사용하면 오류이며, 로컬 최상위 선언이 import 심볼 이름과 충돌하는 것도 오류다.
- `Math.add(...)` 같은 모듈 한정 접근, 선택 import, import alias, 직접 re-export 문법은 없다. 중간 모듈의 IMPORT만으로 그 모듈의 외부 심볼이 다시 공개되지 않는다. 필요하면 새 EXPORT 래퍼/인스턴스를 선언한다.


## 23. 내장 입출력

```kern
GANZ n;
BOOL yes;
CHAR c;
KETTE word[16];
LESEN(n, yes, c, word);
SCHREIBEN(n, " ", yes, " ", c, " ", word);
AUSGABE();
```

| 기능 | 동작 |
|---|---|
| `SCHREIBEN(...)` | 타입에 맞춰 연속 출력, 자동 구분자·줄바꿈 없음 |
| `AUSGABE(...)` | 같은 출력 후 줄바꿈 하나. 인수 없이 쓰면 줄바꿈만 |
| `LESEN(x, ...)` | 하나 이상의 mutable 저장소에 타입별 토큰 입력 |

- 출력: GANZ/LANG은 10진 정수, GLEIT은 최대 9자리 유효숫자 형식, BOOL은 `WAHR`/`FALSCH`. CHAR/KETTE/문자열 리터럴은 Kern 바이트를 UTF-8 문자로 바꾼다.
- 포인터·STRUCT·ENUM·전체 배열은 직접 입출력하지 않는다. 포인터는 INHALT, ENUM은 ordinal cast 후 출력한다.
- 입력은 공백 구분 토큰이다. BOOL은 정확히 WAHR/FALSCH, CHAR는 지원 문자 하나, KETTE는 지원 문자열 하나다. 공백 포함 한 줄 전체를 읽는 내장 함수는 없다.
- 스칼라 입력 토큰은 최대 255 host 바이트다. KETTE 입력은 이 제한 대신 선언 capacity를 적용하며, UTF-8에서 여러 바이트인 문자도 Kern 저장소 한 칸이다.
- 입력 EOF·잘못된 형식·범위 초과·NUL 토큰·미지원 문자·잘못된 UTF-8은 오류다.
- 출력 인수는 왼쪽부터 **모두 평가한 후** 출력한다. KETTE를 포함한 값은 평가 당시 snapshot이다. 뒤 인수에서 원본을 바꾸어도 앞 인수의 출력값은 바뀌지 않는다. 뒤 인수 평가가 실패하면 해당 출력 호출은 아직 출력되지 않았다.
- 반면 LESEN은 인수별 목적지를 평가하고 입력/저장한 뒤 다음 인수를 처리한다. 앞 입력값이 뒤 인덱스 계산에 영향을 줄 수 있다.
- 문자열 리터럴 직접 출력은 첫 NUL에서 끝난다. embedded NUL 뒤까지 길이대로 출력해야 하면 KETTE를 사용한다.

## 24. Kern 82 8-bit 문자셋

| 코드 | 문자 |
|---|---|
| `0x00`–`0x7F` | 표준 ASCII |
| `0x80` `0x81` `0x82` | Ä Ö Ü |
| `0x83` `0x84` `0x85` `0x86` | ä ö ü ß |
| `0x87`–`0xFF` | 유럽 라틴 확장·수학/통화/화살표/선그리기 문자 |

- 전체 표는 현 구현과 일치하는 [독자 문자 코드표](../docs/부록01_독자코드전문.md)를 참고한다.
- 소스 파일은 UTF-8이지만 CHAR/KETTE의 내부 문자는 각각 1바이트다. `'Ü'`는 UTF-8 `C3 9C`가 아닌 Kern **`82`(130)**다.
- LESEN은 UTF-8 → Kern, 출력은 Kern → UTF-8로 변환한다. CHAR를 출력하면 `130`이 아닌 `Ü`가 나온다. 코드값은 `GANZ(c)`로 출력한다.
- 키릴·한글·`ẞ`·`€` 등 없는 문자를 리터럴에 쓰면 명시적 문자셋 오류다. 대체 문자로 조용히 바꾸지 않는다. CP850 호환 모드는 없다.
- 같은 시각적 문자라도 분해된 Unicode 결합열을 자동 정규화하지 않는다. 표에 있는 단일 문자 코드를 사용한다.

## 25. 오류와 런타임 안전성

| 검사 시점 | 대표 항목 |
|---|---|
| 컴파일 | 문법·미지원 문자, 타입/nominal identity 불일치, const 위반, private 접근, copyability, 반환 경로, 상수 CASE·ENUM·배열 크기 |
| 실행 | 정수 범위·실수 비유한 결과·0 나눗셈·잘못된 시프트, 배열/KETTE 범위·용량, NULL 호출/역참조, dangling·UAF, 이중/잘못된 free, 입력 오류 |

검사 실패는 위치를 포함한 진단을 내고 실행을 종료한다. 사용자 코드가 잡는 예외 처리·UNSAFE 우회 문법은 현재 없다. 지역 포인터/참조의 escape를 컴파일 타임 borrow checking으로 막는 모델도 아니다. 수명 종료 후 실제 접근을 런타임에서 검사한다.

## C/Pascal 경험자가 주의할 점

| 다른 언어에서 기대하기 쉬운 동작 | Kern 82 |
|---|---|
| typedef는 별칭 | TYP은 nominal type |
| 짧은 수 → 긴 수 자동 승격 | 일반 변수의 혼합 연산·대입에는 명시 cast 필요 |
| bool/int 혼용 | BOOL 별도 타입, 조건은 BOOL |
| `*p`, `&x`, `p[i]` | `INHALT(p)`, `ADDRESSE(x)`, `INHALT(p + i)` |
| 배열이 자동으로 포인터가 됨 | decay 없음; 최종 원소 주소 취득 |
| `char[]`를 문자열로 취급 | CHAR 배열과 KETTE는 별개 |
| C 문자열의 NUL 종료 | KETTE는 current length; 리터럴 직접 출력과도 차이 있음 |
| 구조체면 항상 복사 가능 | 멤버 루틴·non-copyable 필드가 있으면 복사 불가 |
| 참조 대입으로 대상 교체 | REFERENZ는 fixed binding, 대입은 대상 쓰기 |
| 함수의 호출 순서/인수 평가가 미지정 | 좌→우 평가, 출력은 인수 평가 완료 후 |
| switch 기본 fallthrough / break 종료 | 명시적 FALLTHROUGH / ABBRUCH는 반복문용 |
| 단일 문장 IF / `WHILE ... DO` | BEGIN/END 필수 / `WHILE (조건)` |
| one-past pointer를 만들어도 됨 | 생성 단계에서 범위 오류 |
| signed overflow·dangling·UAF가 UB | 정의된 범위/수명 검사로 오류 처리 |
| free가 포인터를 비우거나 alias를 갱신 | 포인터 값 유지, 공유 수명만 종료 |
| generic 호출에서 타입 추론 | 먼저 NEU로 concrete routine 선언 |
